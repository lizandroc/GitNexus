# Partner-inquiry intake — making the landing page form real

## The problem this fixes

`mylabboxweightloss.com` ships as a static Claude Design export. Its form handler is, in full:

```js
handleSubmit: (e) => {
  e.preventDefault();
  this.setState({ submitted: true });
}
```

There is no endpoint, no `action`, and no `fetch`. The form shows **"Thanks — we've got it!"**
and discards the submission. Every partner inquiry made today is lost, and the prospect
believes they have reached you and is waiting on the "response within one business day" the
page promises.

**Do not send outbound traffic to that page until this is deployed.** A lost inbound lead is
worse than no lead — the prospect thinks you ghosted them.

## What's here

| File | Purpose |
|---|---|
| `worker/src/worker.js` | Cloudflare Worker endpoint — validates, classifies against the campaign ICP, stores, notifies |
| `worker/wrangler.toml` | Worker config; fill in the KV namespace id and notification address |
| `form-capture.js` | Client script that makes the existing form actually send |

Nothing about the page's design or behaviour changes. The visitor sees the same confirmation.

## Why a capture-phase listener rather than editing the form

The page's own handler calls `preventDefault()` and swallows the event, and the markup is
generated by an inline bundler, so there is no stable element to hook. `form-capture.js`
listens for `submit` on `document` in the **capture** phase — it reads the fields before the
page's handler runs, regardless of when the form is rendered. That keeps the fix independent
of the bundler's internals, so re-exporting the page from Claude Design won't silently break it.

The form's inputs have **no `name` attributes**, so fields are matched by their visible label
text. If you rename a label on the page, update `FIELDS` in `form-capture.js` to match.

## Deploy

**1. Create the KV namespace**

```bash
cd campaigns/glp1-retailer-outreach/intake/worker
npx wrangler kv namespace create INQUIRIES
```

Paste the returned `id` into `wrangler.toml`.

**2. Set the notification target**

Email is optional — submissions persist to KV either way.

```bash
# Cloudflare removed the free MailChannels route, so email goes through Resend.
npx wrangler secret put RESEND_API_KEY
# then set NOTIFY_TO in wrangler.toml [vars]

# Optional: also POST every inquiry to Slack / Zapier / your CRM
npx wrangler secret put WEBHOOK_URL
```

**3. Deploy**

```bash
npx wrangler deploy
```

Note the deployed URL.

**4. Wire up the page** (repo: `lizandroc/mylabbox-gpl-1`)

- Copy `form-capture.js` next to `index.html`
- Replace `REPLACE-ME.workers.dev` at the top with your Worker URL
- Add before `</body>` in `index.html`:

```html
<script src="form-capture.js" defer></script>
```

**5. Verify before trusting it**

Submit the live form once with a real address, then:

```bash
npx wrangler kv key list --binding INQUIRIES     # your submission should be listed
npx wrangler tail                                 # watch requests live
```

Do not skip this. The entire point is that a form which *looks* like it works may not.

## What you get per submission

The Worker classifies each inquiry against `../strategy/icp-and-segments.md` before storing,
so inbound arrives already routed:

```json
{
  "id": "…", "receivedAt": "2026-07-29T…",
  "name": "…", "email": "…", "organization": "…", "phone": "…",
  "orgType": "Health system", "volume": "500+ kits", "notes": "…",
  "segment": "S5", "motion": "B", "tier": 1, "sequence": "SEQ-C",
  "volumeScore": 2, "intakeScore": 4, "priority": "high",
  "nyCheckRequired": true, "stage": "Inbound"
}
```

`orgType` → segment mapping matches the form's own dropdown exactly, so inbound and outbound
share one taxonomy.

## Built-in protections

- **Honeypot** — a hidden `company_website` field is injected client-side; anything that fills
  it gets a `200` and is dropped, so bots see success and don't retune.
- **Retry queue** — a submission that fails to send is held in `localStorage` and retried on
  the next page load. Without this, a network blip loses a lead that was already told it
  succeeded.
- **Origin allowlist** — POSTs from anywhere but the configured origins are rejected.
- **Rate limit** — 8 submissions per IP per hour.
- **Size cap** — 16 KB request bodies.
- `keepalive: true` on the send, so closing the tab immediately after submitting doesn't
  cancel it.

## Two things to fix on the page itself

1. **No state field.** The GLP-1 panel is temporarily unavailable in NY, but the form can't
   capture where a prospect operates, so every record is flagged `nyCheckRequired: true` and
   must be confirmed on the first call. Adding a "States you operate in" field would let this
   be filtered at intake instead.
2. **Motion A gate.** The page markets the provider partnership ("earn on every kit"), which
   `../strategy/compliance.md` §1b flags for anti-kickback review. Until that clears, reply to
   clinic inquiries on Motion B terms only. The notification email carries this reminder.

## Testing

Verified end-to-end in Chromium against the real `index.html`:

- all seven fields captured correctly, including the `Organization type` / `Organization`
  label collision
- visitor still sees the unchanged confirmation
- honeypot injected, invisible, and carried on bot submissions
- endpoint unreachable → queued to `localStorage`; reachable again on reload → flushed and
  delivered
- Worker: correct segment/priority for every org type, and correct rejection of missing
  fields, unselected dropdowns, malformed emails, foreign origins and non-POST methods
